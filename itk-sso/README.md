# itk-sso — реестр OAuth-клиентов

Кто вправе пускать людей в ITK через единый вход, что каждому из них разрешено
и что происходило с его токенами.

```
node itk-sso/index.js          # админка на http://localhost:6070
PORT=7546 SSO_DATA_DIR=./data node itk-sso/index.js
npm test --prefix itk-sso      # node --test test
```

## Что внутри

| файл | зачем |
| --- | --- |
| `lib/clients.js` | реестр: создание, правка, вкл/выкл, ротация секрета, проверка пары client_id/secret и допустимости grant/redirect_uri |
| `lib/tokenLog.js` | журнал событий токена: `issued` / `revoked` / `denied` |
| `lib/adminApi.js` | HTTP-ручки админки и раздача страницы |
| `lib/jsonStore.js` | хранилище: JSON-файл с атомарной записью |
| `public/` | страница админки (ванильный JS) |

## Ручки

| метод | путь | что делает |
| --- | --- | --- |
| GET | `/api/clients?enabled=&q=` | список со сводкой по токенам |
| POST | `/api/clients` | завести клиента, секрет возвращается **один раз** |
| GET·PUT·DELETE | `/api/clients/:id` | карточка, правка, удаление |
| POST | `/api/clients/:id/secret` | перевыпустить секрет |
| GET | `/api/token-log?clientId=&event=&subject=&limit=` | журнал, новые сверху |
| POST | `/api/token-log` | записать событие (зовёт сервис выдачи токенов) |
| GET | `/api/meta` | справочник grant types и известных scopes |

## Решения, о которых стоит знать

- **Секрет не хранится.** В реестре лежит scrypt-хеш с солью; строку видно только
  в ответе на создание и на ротацию. Забыли — перевыпускайте.
- **Выключенный клиент не пускают сразу.** `verifySecret` и `checkGrant` на
  `enabled: false` отвечают `disabled` до проверки секрета: выключили — значит
  доступ закрыт, а не «до истечения токена».
- **redirect_uri только https**, без `#`; `http` — исключение для `localhost`.
- **В журнал пишется jti, а не токен.** Журнал читают люди, он не должен
  становиться складом действующих ключей. Хвост старых событий отрезается
  (по умолчанию 5000 последних).
- **Хранилище — файл.** У itk-sso пока нет своей базы (каркас сервиса —
  задача #1945); реестр — десятки строк. `ClientRegistry`/`TokenLog` принимают
  `store` в конструкторе, так что подменить файл на БД — это один класс с
  `read`/`write`/`update`.
- **Без express.** Реестру нужно семь ручек, их отдаёт штатный `http`.
  `createRouter()` возвращает обычный `(req, res, next)` — когда появится каркас
  на node-oidc-provider, он монтируется внутрь него, и отдельный процесс не нужен.
